# 小红书逐字稿：语义审校

默认用大模型直接审校。只有用户明确说「程序化审校／深交」或要求脚本辅助才用脚本。不要混用两种模式。

## 底稿和边界

- 以原始带时间轴字幕为底稿。已有同笔记的点点稿才作为参考，不为审校擅自扩大来源。
- 保留条数、时间戳、顺序和真实的口头重复。只修有依据的识别错词、专名和标点；不补造漏句。拿不准的保留原文，记入待核对清单。
- 只有纯文字时说明限制，请用户提供带时间轴底稿，或确认可以另取；不能从纯文字推测时间点。两份机器稿不能代替原音，未重听时说明只是文本语义审校。

## 两种模式

- **大模型直接审校**：通读带时间轴底稿、已取得的同笔记参考稿和必要上下文，直接写出两份成品；逐条核对条数、时间顺序和替换记录。不生成 `review.json`，不做程序化比对、对齐或自动替换。
- **脚本辅助审校**：在单次临时目录准备原始 SRT；只有带时间轴 Markdown 时可按原有条目和时间点转换，不补造时间点。写 `review.json`：`issues` 仅放确定替换项，`pending` 放待核对项。记录 `id`、`start`（原时间点或总秒数）、`orig`、`suggest`（待核对项可空）、`category`、`confidence`、`reason`。运行 `python3 scripts/semantic_review.py "$WORKDIR"`，检查实际匹配、替换和时间轴；未匹配项记为待核对，不宣称已修改。

## 交付

只交付以下两份 Markdown，放在原笔记目录。不覆盖原稿及历史版本，同名不同内容另存。模型生成的审校文件也要先写临时目录，再归档。

1. `语义审校_带时间.md`：仅带原时间轴的修订稿及基本来源。已知笔记 ID 时，把完整 ID 写入 `- 原笔记：` 字段。
2. `语义审校_记录.md`：注明模式，分「已替换」「待核对」两节。已替换记录时间点、原文 → 新文本及依据；待核对记录时间点、原文、疑点并注明未修改。空节写「无」。

不另出审校纯文字稿，不交付中间 JSON、日志或缓存。单独审校就绪即可交付；讲解任务统一在最终回复交付。
